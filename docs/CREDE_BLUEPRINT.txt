1. PRODUCT IDENTITY
================================================================================

Name:        Crede
Domains:     crede.collab.name.ng (web)
             api-crede.collab.name.ng (API)
             accounts.collab.name.ng (identity / SSO)

Mission:
  Build the most trusted professional identity and talent discovery platform
  in Africa, starting with verified career timelines and AI-assisted CV
  generation.

Positioning:
  Crede is NOT a CV builder.
  Crede is a verified professional identity platform.
  Users maintain a Career Timeline once. That timeline is the source of truth
  for CVs, public profiles, recruiter search, and job matching.

Core principle:
  Store RAW FACTS only in the timeline.
  Never persist AI-generated prose as canonical career data.
  AI is used only for: job description analysis, skill extraction,
  CV tailoring from structured data, opportunity matching assists.

Core object graph:
  Career Timeline
    → Verification
    → CV Generation
    → Public Profile
    → Recruiter Search
    → Job Matching

Feel / design references (target aesthetic):
  LIKE:    ChatGPT Premium, Linear, Raycast, Notion, Vercel, Stripe Dashboard
  NOT LIKE: Canva, Resume.io, LinkedIn, traditional job boards

Design system:
  Font: Inter (fallback system-ui)
  Light: bg #FFFFFF, surface #F8FAFC, border #E2E8F0,
         text #0F172A, muted #64748B, accent #2563EB,
         success #10B981, warning #F59E0B, danger #EF4444
  Dark:  bg #09090B, surface #18181B, border #27272A,
         text #FAFAFA, muted #A1A1AA, accent #3B82F6
  Layout: sidebar 280px, content max 1200px
  Cards: 16px radius, soft borders, no heavy shadows
  Buttons: height 44px, radius 12px

Backend:      FastAPI (Python) — STAY ON FASTAPI

MILESTONE M1 — VPS STORAGE + VERIFICATION TRUST
--------------------------------------------------------------------------------
Goal: Documents and verification proofs live on VPS disk; admins can approve.

Backend:
  [ ] Storage service module: save/read/delete files under /data/crede/...
  [ ] Env: STORAGE_ROOT=/data/crede (or similar)
  [ ] Verification upload endpoint writes to VPS; stores relative path on
      VerificationItem.document_key
  [ ] Certification document upload to VPS
  [ ] Auth-checked download routes (no public directory listing)
  [ ] Admin endpoints (or protected routes):
        list pending verifications
        approve → set status=approved, points, bump verification_score
        reject → status=rejected, notes
  [ ] Ensure refresh_scores runs after approve/reject

Frontend:
  [ ] Verification page: upload control per kind, status, view/download own doc
  [ ] Large circular verification meter UI (score / 100)
  [ ] Simple admin UI page(s) for review queue (Next route guarded by admin role)
  [ ] Empty state: "Increase trust by verifying your credentials."

Acceptance:
  - User uploads employment letter → file on disk → admin approves → score up
  - User can re-download their own uploaded file when authenticated


--------------------------------------------------------------------------------
MILESTONE M2 — REAL CV / DOCUMENT OUTPUTS
--------------------------------------------------------------------------------
Goal: Generate produces real PDF and DOCX on VPS; documents library is usable.

Backend:
  [ ] Template fill → write PDF (reportlab or equivalent) to VPS
  [ ] Template fill → write DOCX (python-docx) to VPS
  [ ] Templates: at least professional + one of modern|executive|minimal
  [ ] Store storage_key_pdf / storage_key_docx on GeneratedDocument
  [ ] Download endpoints for PDF and DOCX (owner only)
  [ ] Optional: Redis queue job "generate_cv" so request returns fast
  [ ] Never write AI free-text back into TimelineEntry

Frontend:
  [ ] /generate: paste JD → show matching insights → Generate
  [ ] After generate: preview summary, Download PDF, Download DOCX, Save version
  [ ] /documents: tabs CVs | Cover Letters | Bios
  [ ] Card actions: download PDF, download DOCX, duplicate (re-queue), delete
  [ ] Empty state: "Generate your first tailored CV."

Acceptance:
  - Generated files exist on disk and download with correct Content-Type
  - Documents page lists versions with dates


--------------------------------------------------------------------------------
MILESTONE M3 — REDIS + MEILISEARCH
--------------------------------------------------------------------------------
Goal: Async jobs and fast recruiter search.

Redis:
  [ ] Connect via REDIS_URL
  [ ] Queue workers (arq or RQ or equivalent) for:
        generate_cv
        reindex_profile
        run_job_matches
  [ ] Optional cache for public profile JSON
  [ ] Rate limit expensive routes (generate, search)

Meilisearch:
  [ ] Deploy Meilisearch; MEILI_URL + MEILI_MASTER_KEY in API env
  [ ] Index `profiles`: full_name, headline, industry, location, skills[],
      years_experience, verification_score, username, is_public,
      onboarding_completed
  [ ] Index `jobs`: title, description, requirements, location, org name,
      status, experience_years_min
  [ ] Reindex profile on timeline/skills/profile update
  [ ] Reindex job on create/update
  [ ] Recruiter candidate search uses Meilisearch (fallback SQL if down)

Acceptance:
  - Recruiter search returns ranked results in <100ms typical on warm index
  - Updating a skill eventually reflects in search (sync or short queue delay)

8. KNOWN OPERATIONAL LESSONS
================================================================================

1. Browser always calls /backend/* — "API base: /backend" on error cards is NORMAL.
2. If /backend/health works without API_PROXY_TARGET, do not add a bad proxy env.
3. Internal Docker hostnames that timeout should not be forced; use what works.
4. Login 200 + /auth/me 200 + /profile/* 500 was schema/profile serialization —
   fixed via external_id + hardened get_or_create_profile + ProfileOut builder.
5. MinIO was painful — VPS disk is the chosen path.
6. curl may be missing inside containers — use browser fetch or python urllib.
